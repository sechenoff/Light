# Человекочитаемый журнал изменений (2026-09-19, PR #219)

**Зачем.** Владелец хочет видеть, кто и из какого аккаунта внёс изменения, точные
дату и время, изменённые поля и понятные русские статусы. Раньше журнал карточки
брони показывал технические имена финансовых событий без автора, а общий журнал —
JSON и фильтр действий только по уже загруженной странице.

**Где.** `/admin/audit`, `/admin/users`, журнал обычной брони и вкладка истории
длинного проекта. `GET /api/audit` поддерживает серверный `action` и `bookingId`
(бронь и связанные финансовые записи), прежние фильтры и пагинацию. Новые сервисы:
`auditContext.ts`, `bookingAudit.ts`, `auditPresentation.ts`. Общий интерфейс —
`auditFormat.ts` и `AuditEntryCard`. Схема базы не меняется.

**Решения владельца.** Русские статусы, аккаунт автора, дата и время, конкретные
изменения. Реализованы две отдельные точки входа из списка пользователей:
«Действия сотрудника» (автор) и «Изменения аккаунта» (объект изменения).
Доступ к общему журналу остаётся у руководителя, прежние права не расширены.

**Правила и инварианты.**
- Снимки показывают различия полей, включая состав и транспорт. Обычная правка,
  создание черновика и быстрой брони записывают аудит в транзакции с изменением.
  Для состава увеличен допустимый размер снимка: старое усечение после 10 КБ
  отбрасывало бы подробности больших броней. Другие писатели сохраняют прежний лимит.
- Контекст автора финансовых событий изолирован на запрос (`AsyncLocalStorage`)
  и берётся из проверенной сессии, без доверия к телу запроса. Фоновое событие
  помечается системой; запрос без аккаунта — неопределённым автором.
- Пользователи, клиенты и связанные записи разрешаются в читаемые названия
  пакетными запросами. Для удалённого объекта используется сохранённый снимок.
- Пароль и хеш не записываются: смена пароля сохраняет только `passwordChanged`.
  Чтение старых снимков также удаляет поля секретов, включая вложенные.
- Даты отображаются и фильтруются по Москве, с секундами. Верхняя граница фильтра
  включает выбранную минуту полностью. Сортировка `createdAt DESC, id DESC`
  детерминирована при совпадающем времени нескольких событий.
- Финансовые события сохранены отдельным раскрываемым блоком. Они не объявляются
  полной историей правок. Старого отсутствующего автора или значения журнал
  не восстанавливает и не выдумывает. Старые записи базы не переписываются.

**Подводные камни.** `before/after` в API — JSON-строки, хотя старый компонент
истории согласования ожидал объект и терял причину отказа. Новый форматтер
принимает оба вида. Финансовые коды оплаты и статусы брони различаются;
`ISSUED` у счёта означает «Выставлен», у брони — «Выдана». Событие быстрой брони
сохраняет прежнее поле `amount` для существующих потребителей. Права на общий
журнал не следуют из доступа к карточке брони: запрос выполняет только руководитель.

**Тесты.** `readableAudit.test.ts` проверяет автора, атомарный откат, фильтры,
пагинацию, секреты, параллельные контексты и большой снимок. Web:
`auditFormat.test.ts`, `AuditEntryCard.test.tsx`, `AuditPage.test.tsx`,
`BookingJournalSection.test.tsx`, существующие тесты подписей и согласования.
Визуальная проверка выполняется на локальных вымышленных данных, без изменений
боевой базы. Скриншоты с данными клиентов не публикуются в репозиторий.
