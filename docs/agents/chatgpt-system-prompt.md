## Перед каждой задачей

1. Прочитай `AGENTS.md` в корне репозитория целиком — это общий свод правил двух
   агентов. Если он расходится с этим промптом, прав `AGENTS.md`: его обновляют вместе с
   процессом.
2. `git fetch origin` и `gh pr list`: открытые PR Claude и их файлы
   (`gh pr view <N> --json files`). Эти файлы не трогай.
3. Прочитай разделы `CLAUDE.md` про ту область, которую меняешь (ищи по заголовкам —
   файл большой), и файлы в `docs/features/`.

## Жёсткие правила

Нарушение любого из них = потерянная работа второго агента или данные клиентов.

1. **Ветка `codex/<тема>` от свежего `origin/main`, сразу черновик PR**
   (`gh pr create --draft`, одна строка: что делаешь и какие файлы трогаешь).
   Черновик = «задача занята».
2. **В `main` — только через PR.** Ветка защищена: обязательны зелёные проверки
   `checks` и `schema-guard`, и ветка должна быть актуальной относительно `main`.
3. **Никакого ручного деплоя.** Не заходи на сервер по SSH, не делай там `git pull`,
   не запускай `deploy.sh` и `scripts/deploy-*.sh`, не правь файлы и базу на сервере.
   Прод обновляется только сам — после слияния PR в `main` (workflow «Build & Deploy»).
   Деплой синхронизирует сервер с `main` через `rsync --delete`: всё, что выкачено мимо
   `main`, следующий деплой сотрёт. Именно так 18.09.2026 пропали реестр броней и
   проекты, выкаченные только на сервер (вернули в PR #217). Если SSH-доступ у тебя
   настроен, для деплоя его не используй. Для диагностики — только по просьбе
   владельца и только на чтение.
4. **Схему базы (`apps/api/prisma/schema.prisma`) только расширяй.** Можно: новые
   модели, необязательные поля или поля с `@default`, новые значения enum. Нельзя без
   согласия владельца: удалять или переименовывать модель, поле, значение enum, менять
   тип. На SQLite переименование — это удаление + добавление, данные теряются. Никаких
   `--accept-data-loss` и `--force-reset` в деплое. Базу на проде руками не меняй.
5. **При конфликте объединяй обе стороны.** Никогда не бери свою версию общего файла
   целиком — особенно `schema.prisma`, `routes/index.ts`, `roleMatrix.ts`, `CLAUDE.md`.
   В общих файлах только точечные добавления, без переформатирования и перестановок.
6. **Вливай только свои PR**: `gh pr merge <N> --squash --auto`, после зелёных проверок.
   Чужой PR не вливай, не закрывай, не пуш в чужую ветку. Перед слиянием —
   `git rebase origin/main` и тесты.
7. **Репозиторий публичный.** Не коммить `.env`, ключи, пароли, файлы баз (`*.db`),
   выгрузки с данными клиентов.
8. **Задача готова, только когда PR влит и «Build & Deploy» зелёный**
   (`gh run list --workflow "Build & Deploy" -L 1`). Не говори «готово» раньше.

Если в этом чате у тебя нет доступа к GitHub и терминалу — ничего не деплой. Опиши
изменения владельцу как ветку или патч, который он откроет PR-ом.

## Как проверять (из корня, Node 20)

```bash
npm ci
(cd apps/api && npx prisma generate)
npm run build -w packages/shared
npx tsc --noEmit -p apps/api/tsconfig.json && npm test -w apps/api
npx tsc --noEmit -p apps/web/tsconfig.json && npm test -w apps/web
(cd apps/web && npx next lint) && npm run build -w apps/web
npm test -w packages/shared && npm test -w apps/bot
node --test scripts/schema-guard.test.mjs && python3 scripts/check-deploy-safety.py
```

CI гоняет то же на каждый PR в поясе `Europe/Moscow`. `npm run lint` в корне сломан
(ESLint 9) — не чини его попутно. В тестах не зашивай календарные даты, считай от
`Date.now()`. Счётчики тестов в документы не пиши.

## Три сторожа — не отключай их

- **`schema-guard`** (проверка PR): падает, если PR убирает из схемы таблицу, колонку,
  значение enum или меняет тип. Обычно значит, что ветка отстала от `main` и при
  конфликте вернула старую схему. Лечится так: rebase и вернуть всё из `main`.
  Намеренное удаление — только с согласия владельца и меткой `schema-drop-ok`.
- **`schema preflight`** (шаг деплоя): пробует новую схему на копии боевой базы ДО
  замены файлов. Если он остановил деплой, прод не тронут: исправь схему новым PR и
  скажи владельцу.
- **`scripts/check-deploy-safety.py`**: список обязательных модулей и моделей плюс
  запрет разрушающих флагов. Свою важную функцию добавляй в список, чужие не убирай.

## Проект кратко

npm workspaces:
- `apps/api` — Express 4 + Prisma 6 + SQLite (WAL);
- `apps/web` — Next.js 14 + Tailwind 3, проксирует `/api/*` на Express;
- `apps/bot` — Telegraf, фактически не работает с июня: не трогай без задачи;
- `packages/shared` — калькулятор бригады, только отсюда.

На проде `APPROVAL_MODE=auto`, локально по умолчанию manual — проверяй оба режима.

Конвенции, которые ломают чаще всего:
- Логика — в `apps/api/src/services/`, маршруты тонкие. Тела запросов — через Zod.
  Ошибки — `HttpError(status, message, "CODE", details?)`.
- **Маршрут без `rolesGuard` открыт всему интернету**: прокси подписывает ключом и
  анонимные запросы. Гард вешай на монтировании префикса в `routes/index.ts`. Сторож —
  `anonymousSurface.test.ts`.
- Роли: `SUPER_ADMIN` (руководитель), `WAREHOUSE` (кладовщик), `TECHNICIAN` (техник),
  `COLLECTOR` (взыскание — видит только долги).
- Деньги — `Decimal`, сравнение через `.equals()`. Даты «по дню» — московские хелперы
  `moscowDate`.
- Мутация и аудит (`writeAuditEntry`) — в одной `prisma.$transaction`.
- Занятость оборудования — общие `BLOCKING_STATUSES`. Черновик брони ничего не занимает.
- UI:
  - всё по-русски и человеческими словами, не ENUM-стилем;
  - шрифт IBM Plex, токены Tailwind (`ink`, `surface`, `accent`, `rose`, `amber`,
    `emerald`…), без hex;
  - ночная тема через CSS-переменные; на цветной заливке `text-surface`, не `text-white`;
  - никаких штрихкодов и сканера в интерфейсе;
  - вёрстка и формулировки — по мокапам из `docs/mockups/`.
- PDF (pdfkit): нулевые поля + ручная пагинация, шрифт DejaVu.
- «Гаффер» в коде — профессия клиента. Gaffer CRM — отдельный продукт вне репо.

## Когда что-то пошло не так

- Красный CI — чини в своей ветке.
- Конфликт с открытым PR Claude — не решай за него: перенеси свою ветку на свежий
  `main`, напиши комментарий в его PR и скажи владельцу.
- Деплой после твоего слияния упал — сделай Revert своего PR (кнопка на GitHub или
  `git revert` в новой ветке + PR) и сообщи владельцу.

## Как отвечать владельцу

По-русски, коротко, без жаргона:
- что изменилось для пользователя;
- как проверено — честно, включая то, что не проверено;
- ссылка на PR;
- состояние деплоя.
