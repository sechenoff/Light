## Как это делают rental-системы

| Система | Что берём |
|---|---|
| **Rentman** — Inventory count → недостача автоматически попадает в *Lost equipment* (модуль Maintenance); lost уменьшает сток; «mark as found» возвращает; кладовщик может пометить lost и на возврате | сверка как источник; «найдено» одной кнопкой |
| **Current RMS / OnRent** — Inventory Check: охват фильтрами (склад/группа/теги), счёт сканом / вручную / CSV; непосчитанное висит в «Exceptions», посчитанное — в «OK»; излишек помечается *Found*; «Submit» создаёт stock-транзакции и *quarantine* (lost/damaged не бронируются); serialized-активы на прошлых заказах авто-принимаются, если физически есть | возобновляемая сессия; излишек = нашлось; ничего не пишется до «Завершить» |
| **Cheqroom** — audits и spot-checks по расписанию, флаг lost/missing прямо в поле, «last seen» (последний custodian) | «след» — кому последнему выдавали |
| **Booqable** — stock counts для bulk-позиций, чтобы находить недостачу | счёт количеств, не сканов |

Общий знаменатель: (1) потерю можно завести не только на возврате; (2) есть пересчёт полки,
который сам показывает расхождения; (3) потеря уменьшает доступность до «найдено»;
(4) «найдено» — одно действие; (5) списание — отдельный, явный исход; (6) видно, где вещь
была в последний раз; (7) есть ответственный и возраст дела; (8) видно деньги под риском.

## Концепты

### A · `concept-a-reestr.html` — «Реестр расследований»
Эволюция текущего экрана. Потеряшка — открытое дело: что пропало, где видели, кто ищет,
сколько висит, чем закончится.
- «**Завести потеряшку**» из реестра (модалка, 3 шага) и из киоска (рядом с «Поломкой»);
- причина «**Не нашли на складе**» + поле **источник** (приёмка / сверка / вручную);
- «**След**» — последние брони, где позиция выдавалась (уже есть в `BookingItem`);
  в модалке — «вероятно здесь» → `sourceBookingId`;
- **ответственный** + «**📣 объявить в поиск**» (карточка на «Моём дне» у всех + задача);
- порядок **по срочности** (горит / в работе / закрытые за 30 дней), поиск, KPI-полоса;
- закрытие в 4 исхода: найдено / не найдено / **списать** / **компенсация в смету** (SA).

### B · `concept-b-sverka.html` — «Сверка склада»
Пропажи находят пересчётом полки, а не по одной.
- под-раздел «**Сверка склада**»: сессия с охватом по категориям, прогрессом, «Отложить»;
- «**по учёту на полке**» = всего − выдано − в мастерской − открытые потеряшки
  (та же формула, что у календаря);
- расхождение → «В потеряшки» / «Нашлось» / «Пересчитать»; запись — только по «Завершить»;
- излишек закрывает открытую потеряшку как «найдено»;
- реестр получает колонку «источник» и историю сверок; отметка «сверено N числа» у позиции;
- ручной ввод из A остаётся вторым путём.

## Сравнение

| | A · Реестр | B · Сверка |
|---|---|---|
| Закрывает просьбу «увидел, что не хватает — добавил, объявил в поиск» | да, напрямую | да, через сессию сверки |
| Схема | `ProblemItem`: + `equipmentId`, `source`, `assignedTo`, `announcedAt`; enum + `NOT_ON_SHELF` | то же **плюс** `StockCount`, `StockCountLine`, `Equipment.lastCountedAt` |
| Новых экранов | модалка + экран киоска + расширение реестра | сессия сверки (десктоп + киоск) + история + расширение реестра |
| Объём | ~3–4 дня | ~7–9 дней (включает A-минимум) |
| Риск | низкий: всё по образцу мастерской v2 | средний: новая сущность, формула «по учёту» должна совпадать с `availability.ts` один в один |
| Когда окупается | сразу: сегодня раздел пуст, потому что в него нельзя попасть | когда пересчёт полки станет регулярным (раз в 2–4 недели по категории) |

**Рекомендация:** делать A целиком, а из B — только фундамент, который всё равно нужен обоим
(`equipmentId`, `source`, новая причина). Сверку — вторым этапом, когда ручной ввод покажет,
сколько пропаж реально всплывает и по каким категориям.

## Открытые вопросы владельцу

1. **Компенсация.** Нужно ли поле «стоимость замены» у позиции каталога, или сумму
   всегда вводит руководитель вручную по факту? От этого зависит, появится ли KPI
   «под риском ₽» и авто-строка в смету.
2. **Списание.** «Списать» уменьшает `totalQuantity` позиции насовсем — делать это
   из потеряшек (SA) или только через карточку оборудования?
3. **Объявление в поиск.** Достаточно карточки на «Моём дне» + задачи, или нужен
   внешний канал (телеграм-бот сейчас мёртв)?
4. **Киоск.** Вкладку «Поломки» переименовать в «Поломки и пропажи» (один экран, два
   сценария) — или отдельная вкладка?
5. **Для B:** позиции на съёмках скрывать из сверки по умолчанию (как в мокапе) или
   показывать с пометкой?
