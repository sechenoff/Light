# AGENTS.md — правила совместной работы агентов

В репозитории параллельно работают два агента: **Claude Code** и **ChatGPT**. Оба
пушат от аккаунта владельца (`sechenoff`), поэтому различаются только префиксом
ветки. Этот файл обязателен для обоих: ChatGPT читает его сам, Claude Code — через
импорт в `CLAUDE.md`. По процессу (ветки, PR, деплой, база) этот файл главнее
всего остального; по устройству кода — `CLAUDE.md`.

| Кто | Ветки | Что делает |
|-----|-------|-----------|
| Владелец | — | ставит задачи, принимает результат на проде, решает спорное |
| Claude Code | `claude/<тема>` | задачи владельца |
| ChatGPT | `codex/<тема>` | задачи владельца |

## 1. Путь на прод — один

`PR → зелёные проверки → слияние в main → «Build & Deploy» (автоматически)`.

- **В `main` напрямую не пушить.** Ветка защищена: только PR, обязательны зелёные
  `checks` и `schema-guard`, ветка должна быть актуальной относительно `main`.
- **Никакого ручного деплоя.** Не заходить на сервер по SSH, не делать `git pull`
  на проде, не запускать `deploy.sh` и `scripts/deploy-*.sh`, не править файлы и
  базу на сервере. Деплой делает `rsync --delete` из `main`: всё, что выкачено мимо
  `main`, следующий деплой сотрёт. Так 18.09.2026 пропали реестр броней и проекты,
  выкаченные только на сервер (вернули в #217).
- **Задача не закончена**, пока PR не влит и прогон «Build & Deploy» не зелёный.
  Красный деплой чинится сразу — новым PR или Revert.
- **Боевая база только для чтения**, и то по просьбе владельца. Данные меняются
  кодом в PR или самим владельцем.
- **Репозиторий публичный.** Не коммитить `.env`, ключи, пароли, базы (`*.db`),
  выгрузки с данными клиентов, скриншоты с персональными данными.

## 2. Как вести задачу

1. `git fetch origin`, затем `gh pr list` — посмотреть открытые PR второго агента и
   их файлы (`gh pr view <N> --json files`).
2. Ветка от свежего `origin/main` со своим префиксом. Сразу открыть **черновик PR**
   (`gh pr create --draft`): заголовок + одна строка «что делаю и какие файлы трогаю».
   Черновик = «задача занята».
3. **Файлы из чужого открытого PR не трогать.** Если без этого нельзя — написать
   комментарий в тот PR и сказать владельцу.
4. PR маленькие, вливаются в течение дня. Долгая ветка — главный источник конфликтов.
5. Перед слиянием: `git rebase origin/main`, тесты локально, CI зелёный.
6. Вливать **только свои** PR: `gh pr merge <N> --squash --auto` (обычный merge-коммит
   запрещён — история линейная). Если `main` ушёл вперёд, PR помечается «отстал» и
   не вливается: `gh pr update-branch <N> --rebase` и дождаться проверок заново.
   Чужой PR не вливать, не закрывать, не пушить в чужую ветку.
7. После слияния дождаться деплоя своего коммита:
   ```bash
   SHA=$(gh pr view <N> --json mergeCommit --jq .mergeCommit.oid)
   gh run list --workflow deploy-rsync.yml --commit "$SHA" -L 1
   ```
   Если прогон отменён или отказался как «устаревший» — это нормально, когда следом
   влили чужой PR: смотри прогон последнего коммита `main`, он включает и твой.
8. При конфликте с чужой работой **сохранять обе стороны**. Никогда не брать свою
   версию файла целиком (`git checkout --ours/--theirs` по общему файлу) — так
   теряется работа второго агента.

## 3. База данных (SQLite + `prisma db push`)

Миграций нет: деплой приводит базу к `schema.prisma`. Поэтому схема — самое
опасное место.

Можно без согласования:
- новые модели (любые поля, `@unique`, `@@unique` — таблица новая и пустая);
- в существующей модели — новое необязательное поле (`String?`) **без** `@unique`
  или поле со значением по умолчанию в базе: `@default("…")`, `@default(0)`,
  `@default(false)`, `@default(now())`;
- новые значения enum, новые `@@index`.

Нельзя без владельца — на заполненной боевой базе это удалит данные или не применится,
и деплой `main` встанет у обоих агентов:
- удалить или переименовать модель, поле, значение enum; сменить тип или `@map`.
  Переименование на SQLite = удаление + добавление. Исторические имена
  (`currentMileage`, `serviceIntervalKm`, …) остаются как есть;
- новое обязательное поле без значения по умолчанию в базе — в том числе
  `@default(cuid())`/`uuid()` (это значения Prisma, не базы) и `@updatedAt`;
- `String?` → `String`; новый `@unique`/`@@unique`/`@@id` на существующей модели.

Enum на SQLite — это просто текст: `db push` не заметит удалённое значение enum, а
чтение строк со старым значением сломается. Здесь `schema-guard` — единственная защита.

Если такое изменение задумано, порядок один: владелец соглашается → **до слияния**
готовит боевую базу вручную, с бэкапом (удаляет данные, чистит дубликаты, заполняет
пустые значения) → на PR ставится метка `schema-drop-ok` → слияние. Метка сама ничего
на проде не делает, она только пропускает PR.

Если деплой `main` остановился на пробе схемы, чини вперёд, новым PR: сделай поле
необязательным или дай ему значение по умолчанию. Revert здесь не поможет: сторож
увидит в нём «удаление поля».

В деплое запрещены `--accept-data-loss` и `--force-reset` (это проверяет
`scripts/check-deploy-safety.py`). Три сторожа, их не отключать:
- `schema-guard` в PR сравнивает схему с `main` по тексту;
- `schema preflight` при деплое пробует схему на копии боевой базы ДО замены файлов;
- сам `db push` без флага отказывается удалять данные.

## 4. Проверки

Из корня (Node 20):

```bash
npm ci
(cd apps/api && npx prisma generate)
npm run build -w packages/shared
npx tsc --noEmit -p apps/api/tsconfig.json && npm test -w apps/api
npx tsc --noEmit -p apps/web/tsconfig.json && npm test -w apps/web
(cd apps/web && npx next lint) && npm run build -w apps/web
npm test -w packages/shared && npm test -w apps/bot
node --test scripts/schema-guard.test.mjs && python3 scripts/check-deploy-safety.py
```

CI (`.github/workflows/ci.yml`) гоняет то же в поясе `Europe/Moscow`.

- `npm run lint` в корне сломан (ESLint 9 без flat-config) — для web `npx next lint`,
  для api хватает `tsc`.
- В тестах не зашивать календарные даты — считать от `Date.now()`.
- Новая функция = тесты: API — интеграционные (изолированная SQLite через
  `prisma db push --force-reset` в `beforeAll`, JWT через `signSession`); web — vitest + jsdom.
- Счётчики тестов в документах не писать: их правит каждый PR, и они конфликтуют.

## 5. Общие файлы — только точечные добавления

`apps/api/prisma/schema.prisma`, `apps/api/src/routes/index.ts`,
`apps/web/src/lib/roleMatrix.ts`, `apps/web/src/lib/rolesMatrix.ts`,
`apps/web/src/lib/auditLabels.ts`, `apps/api/src/services/audit.ts`
(`AuditEntityType`), `scripts/check-deploy-safety.py`, `CLAUDE.md`, `AGENTS.md`.
Здесь можно только добавлять, по месту. Не переформатировать, не переупорядочивать
и не удалять чужие строки. В `check-deploy-safety.py` свой обязательный модуль
добавляется в список, чужие остаются.

## 6. Документация

- `CLAUDE.md` — база знаний о коде: роли, конвенции, разделы по функциям. Читать нужные
  разделы до работы в этой области. Файл большой, ищи по заголовкам.
- Новая функция описывается отдельным файлом `docs/features/<ГГГГ-ММ-ДД>-<тема>.md`:
  зачем, модели, маршруты, решения владельца, подводные камни. В `CLAUDE.md`, в
  раздел «Описания функций», добавляется одна строка со ссылкой. Отдельные файлы
  не конфликтуют между параллельными PR, в отличие от общего.
- Мокапы в `docs/mockups/` — источник правды по вёрстке и формулировкам.

## 7. Проект за минуту

Прокат кинотехники (свет), всё на русском. npm workspaces: `apps/api`
(Express 4 + Prisma 6 + SQLite в WAL), `apps/web` (Next.js 14 + Tailwind 3,
проксирует `/api/*` на Express), `apps/bot` (Telegraf, фактически не работает с
июня — Known Issues №8), `packages/shared` (калькулятор бригады — только отсюда).
Прод: svetobazarent.ru, `APPROVAL_MODE=auto` (локально по умолчанию manual —
проверяй оба режима).

Конвенции, которые ломают чаще всего:

- Бизнес-логика — в `apps/api/src/services/`, маршруты тонкие. Тела запросов —
  через Zod. Ошибки — `HttpError(status, message, "CODE", details?)`.
- **Маршрут без `rolesGuard` открыт всему интернету**: Next-прокси подписывает
  ключом API и анонимные запросы. Гард вешается на монтировании префикса в
  `routes/index.ts`. Новый публичный маршрут добавляется строкой в `PUBLIC_SURFACE`
  (`anonymousSurface.test.ts`).
- Роли: `SUPER_ADMIN` (руководитель), `WAREHOUSE` (кладовщик), `TECHNICIAN` (техник),
  `COLLECTOR` (взыскание: видит только долги).
- Деньги — `Decimal`, сравнение через `.equals()`, никогда `===`.
- Даты «по дню» — московские: `utils/moscowDate.ts` (api) и `src/lib/moscowDate.ts` (web).
- Мутация и её аудит (`writeAuditEntry`) — в одной `prisma.$transaction`.
- Занятость оборудования — общие `BLOCKING_STATUSES` (`PENDING_APPROVAL`,
  `CONFIRMED`, `ISSUED`). Черновик ничего не занимает.
- UI: IBM Plex, токены Tailwind (`ink`, `surface`, `accent`, `rose`, `amber`,
  `emerald`…), без hex и без `slate-*` вне тёмной хромировки. Ночная тема — через
  CSS-переменные. На цветной заливке пишется `text-surface`, а не `text-white`.
- Никаких штрихкодов (`LR-XXX-NNN`) и сканера в интерфейсе и в ответах API для него.
- Подписи по-русски и по-человечески, не ENUM-стилем.
- PDF (pdfkit): нулевые поля в конструкторе + ручная пагинация, шрифт DejaVu для
  кириллицы.
- Gaffer CRM — отдельный продукт вне репо. «Гаффер» в коде — профессия клиента.

## 8. Отчёт владельцу

По-русски, коротко, без жаргона: что изменилось для пользователя, как проверено
(честно, включая что не проверено), ссылка на PR, состояние деплоя. Слово
«готово» — только после зелёного «Build & Deploy».
